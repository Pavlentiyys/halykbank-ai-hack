## О проекте

Агент читает «грязные» кредитные документы и определяет, нарушены ли финансовые ковенанты
корпоративных займов. На каждую ячейку (заёмщик × ковенант) он выдаёт вердикт
`COMPLIANT`/`BREACH`, фактическое значение показателя и транзакцию-доказательство.

Агент рассчитан на ловушки реального документооборота и уверенно их проходит: узнаёт заёмщика
по обезличенному файлу, определяет категорию операции из назначения платежа, отличает
действующий договор от прошлогодней редакции и опирается только на итоговое заключение
аудитора, игнорируя черновики.

### На чём собрано

| Что | Чем |
|---|---|
| Язык и расчёты | Python 3.10+, `Decimal` для денежных величин |
| Чтение документов | [PyMuPDF](https://pymupdf.readthedocs.io/) — текстовый слой PDF напрямую |
| Языковая модель | Gemma `gemma4:e2b` локально через [Ollama](https://ollama.com) |
| Развёртывание модели | [Docker Compose](https://docs.docker.com/compose/) — один контейнер с Ollama |
| Расчёт показателей | Собственная детерминированная модель: банк формул и спецификации |
| Интерфейс | `argparse` и [rich](https://rich.readthedocs.io/) для прогресса и таблиц |
| Тесты и зависимости | `pytest`, [uv](https://docs.astral.sh/uv/) с лок-файлом |

Внешних API и облачных ключей нет: всё перечисленное работает на одной машине. Ниже — почему
выбрано именно это, а в разделе [Стек технологий](#стек-технологий) то же самое с ролью
каждого слоя.

### Почему такие технологии

**Данные не покидают контур.** Кредитные договоры, KYC-досье и банковские выписки — материал,
который в принципе не отправляют во внешний сервис. Поэтому языковая модель здесь локальная:
Gemma через Ollama работает на той же машине, где лежат документы. Ни API-ключей, ни трафика
наружу, ни вопросов о том, где осели корпоративные данные. Тот же прогон можно повторить в
закрытом контуре без интернета.

**Модель по размеру рабочей станции.** `gemma4:e2b` — 5.1B параметров с квантизацией `Q4_K_M`,
в памяти занимает меньше двух гигабайт и держит контекст в 32 тысячи токенов. Ей не нужна
дискретная видеокарта: она одинаково запускается на обычном ноутбуке и на сервере без GPU.
При этом задачи, которые ей поручены, — понять статус документа, разобрать формулировку
ковенанта, отнести платёж к статье — модель такого класса решает уверенно, а тяжёлое
рассуждение ей и не поручается.

**Арифметику считает не нейросеть.** Значение показателя, вердикт и транзакция-доказательство
приходят от детерминированного участника ансамбля на `Decimal`. Это даёт воспроизводимость до
цента и полную прослеживаемость: любой ответ раскладывается на конкретные строки леджера.
Языковая модель отвечает за смысл, числовая — за счёт, и каждая делает то, в чём сильна.

**Docker Compose для модели, а не для всего.** В контейнер вынесена только Ollama: она одинаково
поднимается на macOS, Linux и Windows и держит веса в volume, поэтому повторная установка на
другой машине занимает одну команду. Сам агент остаётся обычным Python-пакетом, который удобно
запускать и отлаживать локально.

**PyMuPDF для документов.** Текстовый слой извлекается напрямую, без распознавания, — это на
порядки быстрее OCR и не вносит ошибок узнавания в числа, от которых зависит вердикт.

### Шаг 4. Данные

В репозитории используются два каталога данных:

```
public/                       открытый тестовый набор с ground_truth.json
private/                      основной набор без ground_truth.json
```

В каждом наборе находятся `master_ledger_2025.csv`, `documents/` и
`submission_template.json`. Для произвольного набора можно передать `--input PATH`.

Состав набора агент определяет сам: список сценариев и номера пунктов читаются из
`submission_template.json`, а соответствие сценария банковскому счёту выводится из леджера.
Поэтому наборы с любым числом заёмщиков и любой нумерацией ковенантов — включая пункты
`5.x` и англоязычные договоры — обрабатываются без правки кода. Незнакомые формулировки
самих ковенантов агент тоже разбирает сам, см. «Как это работает».

## Команды

| Команда | Что делает |
|---|---|
| `run` | Полный прогон датасета → `submission.json` |
| `score` | Оценка готового сабмишна против ключа по официальной формуле |
| `validate` | Сверка структуры сабмишна с шаблоном организаторов |
| `inspect` | Разбор одной ячейки: оценки участников, цитата, документ |

```bash
python -m cli run                                          # основной private-набор
python -m cli run --private                                # то же самое явно
python -m cli run --public                                 # public-набор + тестовый скоринг
python -m cli run --input data/custom --output final.json  # произвольный набор
python -m cli validate                                     # проверка по private-шаблону
python -m cli validate --public                            # проверка по public-шаблону
python -m cli score --public                               # скоринг против public-ключа
python -m cli inspect --scenario S1 --covenant 6.1         # почему такой ответ
```

`--public` и `--private` работают одинаково в `run`, `score` и `validate`, поэтому набор
выбирается одним и тем же флагом на всех шагах.

## Архитектура

Две директории верхнего уровня и строго односторонняя зависимость между ними.

```
                        ┌──────────────────────────────────────┐
   cli/       ─────────►│               model/                 │
   (сегодня)            │                                      │
                        │   Ансамбль: числовая, спеки, gemma   │
   api/       ─────────►│                                      │
   (будущий сервис)     │   Не знает, кто его вызвал,          │
                        │   куда пишется результат             │
   worker/    ─────────►│   и существует ли терминал           │
   (будущая очередь)    └──────────────────────────────────────┘
```

`model/` — самодостаточный пакет: копируется в другой репозиторий и подключается к любому
сервису без единой правки.

```
model/
├── domain/           типы, правила, спецификация расчёта. Нулевые зависимости
├── ports/            Protocol-интерфейсы. Ядро зависит только от них
├── adapters/         PyMuPDF, CSV, Ollama, кэш, библиотека спек — заменяются поштучно
├── ensemble/         участники, политика разрешения, оркестрация
├── services/         контекст, метрики, matching, исполнение спек, пайплайн
├── config.py         Settings — frozen dataclass, без чтения env
└── composition.py    сборка графа объектов: Settings → CovenantPipeline

cli/
├── commands/         run, score, validate, inspect
├── presenters/       rich-прогресс, отчёт, запись файла
├── runtime.py        интерактивная установка Ollama и выбор модели
└── settings.py       .env + argv → model.Settings
```

## Как это работает

### Путь одной ячейки

1. **Разбор документов.** Все PDF читаются один раз. Документ привязывается к заёмщику по номеру
   счёта `ACC-*` в тексте — признак, который однозначно указывает на владельца даже при
   обезличенных именах файлов и отсеивает корпоративный шум вроде пресс-релизов.
2. **Сборка контекста.** Для каждого заёмщика: действующий договор, аудиторское дело, KYC-досье,
   строки леджера, связанные стороны, транзакции с пустой суммой. Здесь же применяются
   корректировки из окончательного заключения: переклассификации статей, исключения по
   отсечению периода, раскрытые курсы валют и суммы, которых нет в леджере отдельной
   операцией, — например поручительства и одобренные овердрафты.
3. **Оценка участниками.** Числовая модель, синтезатор спецификаций и Gemma дают оценку с
   уверенностью по полям. Банк формул подбирает расчёт по тексту пункта: коэффициенты долговой
   нагрузки и покрытия, лимиты расходов по названной статье, квартальные ограничения, отношения
   к выручке. Отдельно поддержаны springing- и двойные тесты, где условие срабатывания и
   отчётный показатель — разные величины: в ответ идёт фактическое значение показателя, как
   того требуют правила организаторов.
4. **Разрешение.** Политика собирает ответ: числа от одного участника, семантика от другого.
5. **Сериализация.** `actual` приводится к модулю и округляется до двух знаков — расходы в
   леджере отрицательные, а по правилам значение всегда положительное.

### Кто за что отвечает

Участники решают **разные** вопросы, поэтому не конкурируют, а закрывают слабости друг друга.

| Что решается | Кто | Почему он |
|---|---|---|
| Действующий документ или устаревшая редакция | **gemma** | Признак текстовый, в шапке страницы |
| Определение ковенанта и порог | **gemma** | Формулировка уникальна у каждого заёмщика |
| Связанные стороны из KYC | **gemma** читает, **числовая** матчит | Таблица — текст, сопоставление — строгое |
| Категория операции по `description` | **gemma** | Колонки категории в леджере нет |
| Незнакомая формулировка ковенанта | **спеки**: gemma описывает расчёт, Python считает | Модель переводит текст в формулу, но не в число |
| `actual` | **числовая** | `Decimal`, без арифметики нейросети |
| `status` | **числовая** | Сравнение с порогом — вычисление, не суждение |
| `evidence_txn_id` | **числовая** | Перебор: какую строку убрать, чтобы вердикт перевернулся |

### Незнакомые ковенанты

Банк формул знает распространённые типы: коэффициенты долговой нагрузки и покрытия, лимиты
расходов по названной статье, отношения к выручке, квартальные ограничения, springing- и двойные
тесты. Когда встречается формулировка, которой в нём нет, включается третий участник.

У модели спрашивается не ответ, а **спецификация расчёта**: какие статьи в числителе, какие в
знаменателе, что вычитается, порог, направление сравнения, охват — период, любой квартал или
четвёртый. Считает по этой спецификации по-прежнему Python на `Decimal`. Промпт при этом
короткий: текст пункта и словарь доступных имён, без документов и леджера.

Разобранная формулировка сохраняется в библиотеку и дальше применяется без обращения к модели.
Ключ строится по тексту пункта с вырезанными числами, поэтому тот же тип ковенанта с другим
лимитом узнаётся как уже знакомый. Файл библиотеки переносится вместе с проектом — на новой
машине разбор уже готов.

Спецификация проходит проверки перед применением: имена сверяются со словарём заёмщика,
коэффициентный ковенант обязан иметь знаменатель, масштаб порога должен соответствовать виду
показателя, а величины уровня Группы отдаются дефолту — их считают по консолидированной
отчётности материнской компании, и собственный леджер заёмщика её не заменяет. При любом
сомнении участник отказывается: он включается только там, где детерминированный расчёт уже
промолчал, поэтому отказ ничего не стоит.

`NumericAuthoritativePolicy` разрешает расхождения по полям: числа берутся у детерминированного
участника, семантика — у языковой модели. Несовпадение вердиктов попадает в `has_disagreement`
и печатается в отчёте — это самый дешёвый признак того, что модель прочитала не тот документ.

Добавить третьего участника — значит написать класс с `Estimator`. Ни `ensemble.py`, ни политика
при этом не меняются.

### Принципы, зашитые в тесты

| Принцип | Где | Тест |
|---|---|---|
| `model/` не знает о `cli/` | запрет импортов, `argparse`, `print` | `test_boundaries.py` |
| `model/` импортируется автономно | копия пакета в чистом каталоге | `test_boundaries.py` |
| `services/` и `ensemble/` не выбирают адаптеры | зависимость только от `ports/` | `test_boundaries.py` |
| Сбой участника не топит ячейку | `try/except` вокруг каждого | `test_ensemble.py` |
